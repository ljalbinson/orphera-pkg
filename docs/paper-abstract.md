# Orphera: a typed, agent-based orchestration framework for small clusters, written in Scala

*Draft abstract.*

Configuration-management tools such as Ansible describe infrastructure in loosely typed YAML, run over SSH, and report failures after the fact. Mistakes in variable names, task ordering or parameters surface only at run time, often halfway through a change to a live cluster. We present Orphera, an orchestration framework that addresses these shortcomings by writing playbooks as compiled Scala programs that run against a small gRPC agent on each managed node. Playbooks are checked by the compiler, and agents stream progress, output and a terminal result for every task. This lets the orchestrator track per-task and per-node outcomes and resume an interrupted run from a checkpoint. Every state-changing command is recorded in an audit log. Orphera runs a chain of playbooks across many configurations in parallel, with per-target logs and a summary, and it builds and bootstraps whole virtual machines from a single command. We describe the design and the stream-termination bug class that agent-based orchestration invites, in which a task fails without sending a final result and the orchestrator waits forever. We evaluate Orphera on a testbed of eight KVM virtual machines across four hypervisors, building and configuring all eight in about eleven minutes, and on cluster deployments of Ceph (cephadm), MariaDB Galera, etcd and WordPress, including teardown and restart tests.
