# Dell OS10 switches: `utils/os10.py`

`utils/os10.py` reads and changes a Dell SmartFabric OS10 switch (tested on an S5148F-ON running OS10 10.4.3.11) through
its RESTCONF API. It needs nothing installed: Python 3 and its standard library, plus `orphera` only to read the password
from the secret store. `make check-os10` tests it against a mock switch on localhost; no switch is needed for that.

## Switching RESTCONF on

RESTCONF is off by default. On the switch:

```
configure terminal
 rest api restconf
 end
write memory
```

It listens on HTTPS port 443 and uses the switch's own users (`admin`). The certificate is self-signed until you install
one, so every command below needs `--insecure` (or `OS10_INSECURE=1`), or `--cacert FILE` with the switch's certificate.

## Login

| What | How |
|---|---|
| user | `--user NAME` or `OS10_USER`; default `admin` |
| password | the Orphera secret named after the switch as typed (`os10.py vlans swt4` reads the secret `swt4`); store it with `echo 'the password' \| orphera secrets set swt4` |
| other ways | `OS10_PASSWORD` in the environment, `--password-file FILE`, `--secret NAME`; with none of these and no such secret, a terminal gets a prompt |

The password is never taken from the command line. A refused login is not retried (repeated failures can lock the account).

## Reading (never changes anything)

```
os10.py interfaces swt4 --insecure      # every port: mode, speed, MTU and the VLANs it carries
os10.py vlans      swt4 --insecure      # every VLAN: how many ports, tagged and untagged
os10.py vlan       swt4 228 --insecure  # one VLAN's ports
os10.py port       swt4 1/1/49:1 --insecure   # one port's settings and VLANs (ethernet1/1/49:1 works too)
os10.py get        swt4 ietf-interfaces:interfaces/interface=vlan228 --insecure   # any path under /restconf/data
os10.py operations swt4 --insecure      # the actions the switch offers (/restconf/operations)
os10.py schema     swt4 yuma-netconf --insecure   # a YANG module's source (a read-only POST of get-schema)
os10.py backup     swt4 [FILE] --insecure   # the whole RESTCONF data tree as JSON (not the CLI configuration)
```

`--json` prints `interfaces`, `vlans`, `vlan` and `port` as JSON instead of a table.

## Changing (running configuration only)

```
os10.py set-description swt4 1/1/5 "gs1 eth0"   # "" removes it
os10.py set-mtu         swt4 1/1/5 9216
os10.py set-speed       swt4 1/1/5 25G          # 10G 25G 40G 50G 100G or auto
os10.py set-mode        swt4 1/1/5 trunk        # trunk, or access (removes the mode)
os10.py vlan-create     swt4 600                # 2-4093
os10.py vlan-delete     swt4 600                # refused while the VLAN has ports
os10.py vlan-add        swt4 600 1/1/5 [--untagged]   # tagged unless --untagged
os10.py vlan-remove     swt4 600 1/1/5
os10.py save            swt4                    # copy running-configuration startup-configuration
```

Every change shows the old and the new value and asks for `yes` (`--yes` skips it, and is required without a terminal);
`--dry-run` shows the request and sends nothing. After sending, the tool reads the object back and fails if the switch did
not take the change. Only ethernet ports can be changed; VLAN 1 cannot be created or deleted, but ports can be put back
into it (`vlan-add swt4 1 1/1/5 --untagged`).

### What was learned on the switch

- **Nothing is saved automatically.** A change made through RESTCONF is in the running configuration only; a reload undoes
  it until `os10.py save` (a `yuma-netconf:copy-config` from running to startup) or `write memory` on the switch.
- **A missing VLAN or port is HTTP 400** ("unknown resource instance"), not 404; the tool reports it as "no VLAN" or
  "no port".
- **A port must be in trunk mode to carry tagged VLANs.** The switch refuses otherwise ("not in switchport mode trunk").
  Use `set-mode trunk` first; `set-mode access` removes the mode again.
- **Untagged add moves the port.** The switch moves a port out of the VLAN it was untagged in when it is added untagged
  to another. Taking it out of the old VLAN first made the switch answer HTTP 500, so the tool asks for the direct add,
  and only if the switch refuses it takes the port out of the old VLAN first (and puts it back if the second step fails).
- **Creating a VLAN** is a `PUT` of the VLAN interface; if a switch answers that with 405 or 501 the tool tries `POST`.
- **Speed** values are the switch's own (`25GIGE`, `10GIGE`); `auto` and the other speeds are passed on as given and the
  switch says if it does not accept one.

Do not change the speed or MTU of, or move, the port you reach the switch through, and use `--dry-run` first on any port
that carries traffic.

## Exit codes

0 done, 1 the switch failed or refused, 2 wrong usage. Errors print as `FAIL  ...` on standard error.
